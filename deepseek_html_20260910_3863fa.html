┌─────────────────────────────────────────────────────────────┐ │ BROWSER (User's Machine) │ │ http://<server-ip>:9090 │ └──────────────────────┬──────────────────────────────────────┘ │ HTTP (same origin) ▼ ┌─────────────────────────────────────────────────────────────┐ │ LINUX SERVER (Docker Host) │ │ │ │ ┌────────────────────────────────────────────────────┐ │ │ │ Docker Network: user-mgmt-net │ │ │ │ │ │ │ │ ┌─────────────┐ ┌─────────────┐ ┌────────────┐ │ │ │ │ │ frontend │─▶│ backend │─▶│ mysqldb │ │ │ │ │ │ (Angular │ │ (Spring │ │ (MySQL │ │ │ │ │ │ + Nginx) │ │ Boot) │ │ 8.0) │ │ │ │ │ │ :80 │ │ :2002 │ │ :3306 │ │ │ │ │ │ host:9090 │ │ host:2002 │ │ host:3306 │ │ │ │ │ └─────────────┘ └─────────────┘ └────────────┘ │ │ │ │ │ │ │ │ Volume: mysql-data (persistent) │ │ │ └────────────────────────────────────────────────────┘ │ └─────────────────────────────────────────────────────────────┘

Request Flow

  1. User opens http://<server>:9090
  2. Nginx (frontend container) serves Angular HTML/JS
  3. Browser executes Angular → calls /api/users (relative path)
  4. Browser sends request to http://<server>:9090/api/users
  5. Nginx proxies /api/ → http://backend:2002/api/users
  6. Spring Boot receives request
  7. Spring calls UserService → UserRepository → Hibernate
  8. Hibernate queries MySQL at mysqldb:3306
  9. MySQL returns rows
  10. Spring serializes to JSON
  11. Nginx relays response to browser
  12. Angular renders table

4.5 API Service

File: src/app/services/user.service.ts

import { Injectable } from '@angular/core';
import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Observable, throwError } from 'rxjs';
import { catchError } from 'rxjs/operators';
import { User } from '../models/user.model';

@Injectable({ providedIn: 'root' })
export class UserService {
  // Relative path — Nginx proxies /api/* to backend container
  private readonly API_BASE = '/api/users';

  constructor(private http: HttpClient) {}

  getAll(): Observable<User[]> {
    return this.http.get<User[]>(this.API_BASE)
      .pipe(catchError(this.handleError));
  }

  getById(id: number): Observable<User> {
    return this.http.get<User>(`${this.API_BASE}/${id}`)
      .pipe(catchError(this.handleError));
  }

  create(user: User): Observable<User> {
    return this.http.post<User>(this.API_BASE, user)
      .pipe(catchError(this.handleError));
  }

  update(id: number, user: User): Observable<User> {
    return this.http.put<User>(`${this.API_BASE}/${id}`, user)
      .pipe(catchError(this.handleError));
  }

  delete(id: number): Observable<void> {
    return this.http.delete<void>(`${this.API_BASE}/${id}`)
      .pipe(catchError(this.handleError));
  }

  private handleError(error: HttpErrorResponse) {
    let message = 'Something went wrong';
    if (error.error instanceof ErrorEvent) {
      message = `Client error: ${error.error.message}`;
    } else if (error.error?.errors && typeof error.error.errors === 'object') {
      message = Object.entries(error.error.errors)
        .map(([f, m]) => `${f}: ${m}`).join(', ') || error.error.message;
    } else {
      message = error.error?.message || `Server error: ${error.status}`;
    }
    console.error('[UserService]', message, error);
    return throwError(() => new Error(message));
  }
}

5.8 CORS Configuration

File: config/CorsConfig.java

@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS", "PATCH", "HEAD")
                .allowedHeaders("*")
                .exposedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
⚠️ Key insight Use allowedOriginPatterns (not allowedOrigins) when allowCredentials(true). Spring rejects wildcards in the latter.

# Stage 1: Build Angular
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .

# Stage 2: Serve with Nginx
FROM nginx:stable-alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist/*/browser /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

nginx.conf:

server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;

    # Proxy API calls to backend container
    location /api/ {
        proxy_pass http://backend:2002/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_method $request_method;
    }

    # Angular SPA routing
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Static asset caching
    location ~* \.(?:css|js|jpg|jpeg|gif|png|svg|ico|woff2?)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

8. Key Concepts Learned

Docker

  • Multi-stage builds — build with Maven/Node, run with minimal JRE/Nginx
  • Container networking — containers reach each other by name
  • Volumes — mysql-data persists database across container restarts
  • Health checks — Docker detects when a service is ready
  • .dockerignore — keeps image small by excluding junk
  • --env-file — cleaner than many -e flags

Nginx

  • Reverse proxy — forward /api/* to another service
  • SPA routing — try_files $uri $uri/ /index.html for Angular
  • Gzip compression — smaller responses
  • Static asset caching — faster repeat visits

Spring Boot

  • Environment variables — application.properties reads ${VAR}
  • @RestControllerAdvice — global exception handling
  • JPA/Hibernate — entity ↔ table mapping
  • Bean validation — @NotBlank, @Email
  • CORS — allowedOriginPatterns vs allowedOrigins

Angular

  • Standalone components — no NgModule needed
  • Services — singleton, providedIn: 'root'
  • RxJS Observables — async data streams
  • Relative URLs — /api/users works behind proxies

Networking

  • localhost inside container = the container itself
  • Container name = DNS name on Docker network
  • Same origin = browser doesn't trigger CORS
  • Preflight OPTIONS — browser asks permission before PUT/DELETE

9. Problems & Solutions

Every real project hits obstacles. Here is the complete log of every problem we encountered during this build, along with the diagnosis and fix — 21 issues total.

1
Git Repository Initialized in Wrong Directory
Symptom

fatal: not a git repository (or any of the parent directories): .git

Root Cause

Ran git init inside C:\Users\dasar\ (home directory) instead of the project folder. Git treated the entire home directory as a repository.

Fix 
cd C:\Users\dasar
Remove-Item -Recurse -Force .git
cd C:\Users\dasar\Downloads\frontend_user-management
git init
Lesson

Always cd into the exact project folder before running git init. Verify with git rev-parse --show-toplevel.

2
Node.js / npm Not Recognized
Symptom

'node' is not recognized as an internal or external command

Root Cause

Node.js wasn't installed, or the PowerShell session hadn't picked up the new PATH after installation.

Fix

Install from nodejs.org, then close and reopen PowerShell (crucial). Verify with node -v and npm -v.

Lesson

After installing any tool, always restart the terminal to reload PATH.

3
Docker Not Installed / Daemon Not Running
Symptom

docker: command not found or Cannot connect to the Docker daemon

Root Cause

Docker Desktop wasn't installed, or the daemon service wasn't running.

Fix

Install Docker Desktop, restart PC, launch the app, wait for the whale icon to stabilize. Verify: docker --version and docker ps.

Lesson

Docker needs the daemon running — not just the CLI. Always check docker ps first.

4
Port 8080 Already in Use (Jenkins Conflict)
Symptom

Error starting userland proxy: listen tcp4 0.0.0.0:8080: bind: address already in use

Root Cause

Jenkins CI/CD was running on port 8080 (a common default). Docker couldn't bind to it.

Fix

Diagnose: ss -tulpn | grep :8080. Then use a different host port: docker run -p 9090:80 ...

Lesson

8080 is the most contested port in DevOps. Check availability before assigning.

5
Port 3000 EACCES on Windows
Symptom

Error: listen EACCES: permission denied ::1:3000

Root Cause

Windows reserves certain port ranges (3000-3060, 5000, etc.) for Hyper-V and system services via netsh.

Fix

Check reserved ranges: netsh interface ipv4 show excludedportrange protocol=tcp. Then use an unreserved port — we chose 4000 for json-server.

Lesson

On Windows, some ports are off-limits even if nothing appears to use them.

6
MySQL Container Reports Unknown Database
Symptom

java.sql.SQLSyntaxErrorException: Unknown database 'user_management_db'

Root Cause

The database was never created in the MySQL container. Spring Boot assumed it existed and failed on startup.

Fix

Two approaches used. First manually: CREATE DATABASE user_management_db;. Later made it reproducible by baking an init.sql into a custom MySQL image.

Lesson

Containers don't come with databases. Use init.sql in /docker-entrypoint-initdb.d/ for reproducibility.

7
Backend Can't Reach MySQL Container
Symptom

java.sql.SQLException: Communications link failure

Root Cause

Backend and MySQL containers were on different Docker networks. Backend's localhost referred to itself, not MySQL.

Fix 
docker network create user-mgmt-net
docker network connect user-mgmt-net mysqldb
docker network connect user-mgmt-net backend

Then use the container name as hostname: jdbc:mysql://mysqldb:3306/...

Lesson

Container names are DNS names on custom networks. localhost never works between containers.

8
Access Denied for 'root'@'172.18.0.3'
Symptom

java.sql.SQLException: Access denied for user 'root'@'172.18.0.3' (using password: YES)

Root Cause

We used a placeholder (YOUR_MYSQL_PASSWORD) instead of the real password.

Fix

Found the real password: docker exec mysqldb env | grep MYSQL_ROOT_PASSWORD. Updated backend.env with the actual value.

Lesson

Placeholders look similar to real passwords. Always verify before assuming.

9
@NotBlank Cannot Be Resolved
Symptom

NotBlank cannot be resolved to a type in Eclipse

Root Cause

Spring Boot's validation starter was missing. Since Spring Boot 2.3, hibernate-validator isn't included by default.

Fix 
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

Then right-click project → Maven → Update Project (Alt+F5).

Lesson

Validation is a separate starter. Add it explicitly when using @NotBlank, @Email, etc.

10
Invalid Maven Artifact Names in pom.xml
Symptom

Could not find artifact org.springframework.boot:spring-boot-starter-webmvc

Root Cause

The generated pom.xml had wrong artifact names. Spring Boot has ONE test starter, not one per module.

Fix

Replaced the entire pom.xml dependencies block:

  • ❌ spring-boot-starter-webmvc → ✅ spring-boot-starter-web
  • ❌ spring-boot-starter-actuator-test → ✅ spring-boot-starter-test
  • ❌ spring-boot-starter-data-jpa-test → ✅ spring-boot-starter-test
  • ❌ spring-boot-starter-webmvc-test → ✅ spring-boot-starter-test
Lesson

Never trust generated pom.xml blindly. Verify artifact names on Maven Central.

11
Spring Boot 3.2.x End-of-Life Warnings
Symptom

OSS support for Spring Boot 3.2.x ended on 2024-12-31

Root Cause

The project was generated with an outdated Spring Boot version.

Fix

Changed <version>3.2.5</version> to <version>3.5.16</version> in pom.xml, then Maven → Update Project.

Lesson

Always use the latest stable version for new projects. Old versions stop getting security patches.

12
Content-Type 'text/xml' Not Supported
Symptom

{"message":"Content-Type 'text/xml;charset=UTF-8' is not supported","status":500}

Root Cause

The POST request was missing the Content-Type: application/json header, so Spring defaulted to XML handling and rejected the JSON body.

Fix 
curl -X POST http://localhost:2002/api/users \
  -H "Content-Type: application/json" \
  -d '{"firstName":"John",...}'
Lesson

REST APIs require explicit Content-Type headers. curl doesn't add JSON type automatically.

13
403 Forbidden on POST/PUT/DELETE (CORS Preflight)
Symptom

Delete failed: Server error: 403. Preflight OPTIONS returned 403 Invalid CORS request.

Root Cause

Two compounding issues:

  1. CorsConfig had a fixed allowedOrigins list (4200, 4201, 59153) that didn't include 9090
  2. Spring rejects allowedOrigins("*") when allowCredentials(true) is set
Fix

Used allowedOriginPatterns instead — supports wildcards with credentials:

registry.addMapping("/api/**")
    .allowedOriginPatterns("*")
    .allowedMethods("GET","POST","PUT","DELETE","OPTIONS","PATCH","HEAD")
    .allowedHeaders("*")
    .exposedHeaders("*")
    .allowCredentials(true)
    .maxAge(3600);
Lesson

allowedOrigins vs allowedOriginPatterns — the latter is required for wildcards with credentials enabled.

14
Nginx Not Forwarding DELETE/PUT
Symptom

GET via proxy worked; POST/DELETE returned 403 from Nginx.

Root Cause

Nginx's default proxy behavior doesn't forward all HTTP methods unless explicitly told to.

Fix

Added method forwarding and proper headers to nginx.conf:

location /api/ {
    proxy_pass http://backend:2002/api/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_method $request_method;
}
Lesson

Nginx proxies are not transparent by default. Explicitly allow methods and set headers.

15
Container Name Conflict
Symptom

Conflict. The container name "/backend" is already in use by container "f7ada54ff57f..."

Root Cause

An old container with the same name still existed (in Exited state) from a previous failed run.

Fix 
docker rm -f backend
docker run -d --name backend ...

Or one-liner:

docker rm -f backend 2>/dev/null; docker run -d --name backend ...
Lesson

Docker won't let you reuse a name. Always clean up before rerunning.

16
Docker Image Build Cached Wrong Version
Symptom

Rebuilt image but new code didn't take effect — old CORS error persisted.

Root Cause

Docker's layer caching reused old layers, or we ran :v1 while the new image was tagged :v2.

Fix
  1. Use versioned tags: v1, v2, v3
  2. Force rebuild: docker build --no-cache -t ... .
  3. Remove old image: docker rmi user-management-backend:v2
Lesson

Docker tags matter. When in doubt, use unique tags per build and verify with docker images.

17
Backend Container Exits Immediately
Symptom

docker ps shows backend as "Exited (1)".

Root Cause

Spring Boot couldn't initialize — wrong DB password, unreachable DB, missing env vars, or port conflict inside container.

Fix

Always check logs first:

docker logs backend

The Java stack trace tells you exactly what failed. In our case: Access denied for user 'root' — fixed by using the correct password in backend.env.

Lesson

Container exits are always logged. docker logs <name> is your first diagnostic command.

18
Port 9090 "Already in Use"
Symptom

bind: address already in use when starting frontend on 9090.

Root Cause

An old frontend container was still holding port 9090.

Fix 
docker rm -f frontend
docker run -d -p 9090:80 ...
Lesson

Before running new containers, always remove old ones with the same name or port.

19
Angular Build Fails with npm ci
Symptom

npm ci can only install packages when your package.json and package-lock.json are in sync

Root Cause

package-lock.json was missing or out of date. npm ci requires an exact lock file.

Fix

Either commit package-lock.json to the repo, or change Dockerfile to use npm install instead of npm ci.

Lesson

npm ci is stricter and faster, but requires a lock file. For fresh projects, use npm install.

20
Frontend Still Showing Old Placeholder Text
Symptom

Browser displayed "User List works!" instead of the actual user table.

Root Cause

The component was still the placeholder generated by ng generate component — the real code was never applied.

Fix

Replaced the placeholder user-list.component.ts with the real component, plus its HTML/CSS files.

Lesson

When scaffolding components, always verify the file contents changed. Placeholder text is a red flag.

21
Docker Network Not Persisting Between Restarts
Symptom

After restarting the MySQL container, backend lost connection.

Root Cause

docker run without --network attaches the container to the default bridge, not our custom network. Starting a stopped container sometimes reassigns networks if it was created without one.

Fix

Always specify --network user-mgmt-net when creating containers. If a container already exists without it, connect it manually:

docker network connect user-mgmt-net mysqldb
Lesson

Networks are set at container creation. To change later, use docker network connect.
